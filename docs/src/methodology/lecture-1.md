# ЛЕКЦИЯ 1 

## 1. Исполнители и алгоритмы

Прежде чем достаточно полно ответить на вопрос, что же такое алгоритм, потребуется сначала определить абстрактное понятие исполнителя, потому что, всякий алгоритм адресуется некоторому исполнителю.

Под **исполнителем** понимается некоторое устройство (автомат), которому присущи, во-первых, некоторое множество внутренних состояний, в каком-то одном из которых он находится в текущий момент времени, и, во-вторых, - некоторый конечный набор (множество) команд, каждую из которых исполнитель выполняет при получении соответствующего предписания (сигнала).

При этом необходимо отметить что: 

-  в каждый момент времени исполнитель находится в каким-то одном из состояний и самопроизвольно перейти в другое состояние он не может (здесь время мыслится дискретным, т.е. шкалу времени можно представлять в виде ряда натуральных чисел);
-  переходы из состояния в состояние возможны только при выполнении некоторых команд исполнителя; 
-  в какое именно состояние перейдет исполнитель при выполнении команды - это однозначно определяется его начальным состоянием и тем, какая именно команда им выполняется.

Множество всех команд исполнителя называется его командным интерфейсом.

Исполнитель может представлять собой, например, некоторое внешнее устройство, подключенное к компьютеру (от которого он получает предписания на выполнение команд). Но исполнитель может представлять собой и некоторый программный код+данные, размещенные в памяти компьютера, при этом состояние соответствующей части памяти компьютера будут определять состояние этого исполнителя. Многие компоненты компьютера (такие как память, отдельные блоки процессора, но весь процессор целиком, все периферийные устройства, подключенные к компьютеру через соответствующий интерфейс) так же являются исполнителями в смысле данного определения.

Переменные, объекты различных типов (классов), размещенные в памяти компьютера в совокупности с определенными для них операциями и функциями, программные модули - все это примеры исполнителей.

Перейдем теперь собственно к определению того, что мы будем понимать под алгоритмом.

**Алгоритмом** называется каким-либо образом определенный порядок **конечного числа** каких-либо команд исполнителя, переводящий исполнителя из заданного **начального состояния** в требуемое **конечное состояние**.

Важно подчеркнуть, что такой переход из **начального состояния** в **конечное состояние** осуществляется в результате выполнения **конечного числа** команд исполнителя.

При этом и **начальное состояние,** и **конечное состояние** обычно задаются в виде некоторых условий.

Например, чтобы извлечь квадратный корень из заданного вещественного числа x, должно быть выполнено условие:
```julia
    ДАНО: x ≥ 0
```
При этом требуемый результат, получаемый в переменной y, должен подчиняться условию:

```julia
    РЕЗУЛЬТАТ: y^2 == x.
```
Или, что для компьютерных вычислений с плавающей точкой более реалистично,
```julia
    ДАНО: 
    - x ≥ 0 - значение числа
    - ε > 0 - максимально допустимая погрешность вычислений

    РЕЗУЛЬТАТ: |y^2 - x| <= ε
```
**Замечание**
Выражения вида $x≥0$,  $y^2 == x$, $|y^2 - x| ≤ ε$ в математике называются **предикатами**.

В общем случае, **предикат** - это какая-либо функция от некоторого числа переменных (каких-либо типов), отображающая заданный набор значений своих аргументов в `{true, false}`. В примерах первый предикат зависит только от переменной $x$ второй - от $x$ и $y$, третий - от $x$, $y$ и $ε$.

Таким образом, чтобы описать какой-либо алгоритм, т.е. чтобы четко сформулировать, что алгоритм должен делать, фактически требуется определить два предиката: "ДАНО" и "РЕЗУЛЬТАТ". Аргументом этих предикатов будет внутреннее состояние исполнителя (если понимать состояние, как нечто целое).

## 2. Языки программирования высокого и низкого уровней, исходный код, трансляция в исполняемый код (в машинные инструкции)

Алгоритмы, как правило, записываются на **языках программирования высокого уровня** (алгоритмических языках).

Различных алгоритмических языков (языков программирования высокого уровня) очень много.

Они называются языками высокого уровня, потому, что эти языки ориентированы на то, чтобы быть удобными для понимания человеком. В противоположность к этому существуют также **языки низкого уровня** - это языки машинных команд. Для каждого типа процессора имеется свой язык.

На языках машинных команд записываются двоичные коды машинных инструкций (в определенном формате), такие языки очень трудны для восприятия человеком. Для облегчения восприятия языка машинных команд существуют специальные языки, называемые **ассемблерами**. Ассемблеры очень близки к машинным языкам, фактически ими и являются, только вместо двоичных кодов машинных инструкций в ассемблерах используются мнемонические имена - специальные ключевыми слова ("мнемонические" - это значит, намекающие на назначения соответствующих команд).

Запись алгоритма на языке высокого уровня представляет собой некоторый текст, составленный по определенным правилам, и называемый **исходным кодом**. Этот текст, т.е. исходный код, должен быть преобразован в другой текст, представляющий собой соответствующую запись машинных инструкций (двоичных кодов), определяющую порядок выполнения этих инструкций, т.е. в **машинный код**.

Преобразование исходного кода в машинный код называется трансляцией.

**Трансляция** осуществляется автоматически с помощью специальных программ, называемых **трансляторами**. Обычно "исходными данными" для транслятора является текстовый файл, содержащий исходный код.

## 3. Устройство реального компьютера

Выше мы рассмотрели устройство абстрактной машины Тьюринга. Теперь же рассмотрим, как устроены реальные компьютеры.

Современные компьютеры часто являются многопроцессорными, а современные процессоры обычно являются многоядерными. Но мы для простоты ограничимся рассмотрением устройства компьютера лишь с одним одноядерным процессором.  

 В многоядерной системе одновременно может выполняться несколько изолированных вычислительных процессов. Поэтому можно считать, что следующее наше рассмотрение устройства компьютера будет относится лишь к архитектуре вычислительных ресурсов, выделяемым одному единственному процессу.

Будем говорить о так называемой Фоннеймановской архитектуре компьютера, которая в настоящее время является наиболее распространенной.

Фоннеймановская архитектура включает следующие элементы:

-     основная память (ОП) с единым адресным пространством
-     центральный процессор (ЦП)
-     шина
-     устройства ввода-вывода (монитор, клавиатура, мышь, диск)  
-     возможны дополнительные периферийные устройства (внешние носители данных, принтеры, сканеры и т.п.)

**Шина** - это, упрощенно говоря, многожильный провод, по которому различные элементы компьютера обмениваются информацией по специальному протоколу посредством передачи электрических сигналов.

Феймановская архитектура характеризуется тем, что и данные и исполняемый программный коды размещаются в ОП с единым адресным пространством. Кроме Феймановской архитектуры известна также так называемая Гарвардская архитектура, в которой для данных и для программного кода используются отдельные адресные пространства. 

Современные процессоры как правило имеют Фоннеймановскую архитектуру, однако, иногда Гарвардская архитектура реализуется в виде некоторой виртуальной машины. 
### 3.1 Основная память (ОП)

-  ОП представляет собой занумерованную последовательность байтов (нумерация начинается с 0).
-  Каждая порция данных занимает в памяти целое число байтов.
-  Номер байта, с которого начинается размещение тех или иных данных, называется **адресом** этих данных.
-  Размер адресного пространства определяется разрядностью машины, например, для 64 разрядной машины её адресное пространство представляет собой диапазон от 0 до 2^64-1.
-  В ОП в едином адресном пространстве размещаются как данные, так и программные коды (это есть отличительная характеристика именно Фоннеймановской архитектуры).

### 3.2 Центральный процессор (ЦП)

Современные процессоры как правило являются многоядерными. Каждое ядро любого ЦП содержит следующие элементы:

-  арифметико-логическое устройство (АЛУ);
-  регистры общего назначения;
-  регистры специального назначения;
-  командный регистр (в частности);
-  стековый регистр (в частности);
- кеш-память (обычно 3х уровней L1, L2, L3)
-  устройство управления (УУ);

**AЛУ** представляет собой электронную схему, выполняющую арифметические и логические операции, предварительно помещенные в специальные ячейки памяти, называемые регистрами

**Регистры общего** назначения обеспечивают работу АЛУ.

Вообще **регистры ЦП** отличаются от обычных ячеек памяти, используемых в ОП, тем что они выполнены по специальной (очень дорогой) технологии, обеспечивающей предельно высокую скорость работы этой памяти (запись - считывание).

Среди регистров специального назначения особо важное значение имеют командный и стековый регистры.

**Кеш-память** используется для ускорения работы процессора над данными, размещенными оперативной памяти. Оперативная память относительно медленная  (имеет относительно большое время считывания/записи). Поэтому данные, которые по прогнозу понадобятся процессору в ближайшее время перемещаются в быструю кеш-память. Такой прогноз осуществляется в системе автоматически. При этом, конечно, возможны ошибки такого прогноза, называемые кеш-промахами. Кеш-промахи могут приводить к очень сильному замедлению выполнения программы.  Поэтому квалифицированный разработчик прикладной программы должен понимать, в каких ситуациях будут происходить ошибки автоматического прогноза и уметь правильно размещать данные в оперативной памяти, чтобы минимизировать кеш-промахи.

**УУ** представляет собой электронную схему, обеспечивающую автоматическое выполнение программного кода, под управлением которого в данный момент работает компьютер.
#### _3.2.1 Назначение командного регистра и алгоритм работы компьютера_
Выше мы рассмотрели логику работы ДМТ. Рассмотрим теперь логику работы реального компьютера.  Для обеспечения автоматического выполнения программного кода в реальном компьютере используется так называемый **командный регистр**.

**Командный регистр** - это специальная ячейка памяти, где всегда хранится адрес команды, которая будет выполняться следующей. С его помощью обеспечивается работа УУ процессора следующим образом.
```julia
while true # цикл выполняется бе конца
    #1 -  прочитать адрес команды из командного регистра;
    #2 -  увеличить значение командного регистра на длину кода прочитанной команды;
    #3 -  выполнить прочитанную команду; 
end
```
Здесь, по-видимому, требуются следующие уточнения.

1)   Машинный код занимает где-то в памяти компьютера некоторый непрерывный сегмент, начиная с некоторого адреса, котором коды команд следуют последовательно, команда за командой.

2)   Разные команды могут иметь разную длину своего кода, т.к. кроме собственно кода команды у нее имеются еще некоторое число параметров, располагающиеся сразу после кода команды, которое у разных команд, вообще говоря, разное.

3)    Может показаться, что описанная логика работы компьютера не предполагает наличия ветвлений или циклов, т.к. код, якобы, всегда выполняется только в линейной последовательности; однако это не так: дело в том, что среди процессорных команд есть и такие, которые сами изменяют содержимое командного регистра; с помощью таких команд и реализуются, как циклы, так и ветвления.

При включении компьютера обычно сначала запускается ОС. Затем под управлением этой ОС могут быть запущены уже другие программы, которым ОС передаст  управление (т.е. по указанному выше алгоритму фактически будет выполняться уже код того или иного запущенного приложения), но при этом ОС продолжит функционировать в фоновом режиме, активизируясь при наступлении некоторых событий. Точнее говоря, ОС имеет так называемое ядро, и это ядро всегда загружено в ОП, и при необходимости в любой момент может перехватить управление. Такие программы, подобные ядру ОС называются резидентными.

#### _3.2.2 Стековый регистр и механизм вызова подпрограмм_

В программировании под **стеком** (от англ. stack — стопка) понимают динамическую последовательность элементов данных в памяти, добавление нового элемента в которую или извлечение уже записанного элемента из которой возможно осуществить только с одного её конца (всегда одного и того же), называемого **вершиной стека**.

При операциях добавления/удаления элемента в стеке реализуется принцип: «последним пришел — первым ушел», наглядным образом которого может служить стопка тарелок (при условии, что ни снизу, ни из середины стопки тарелки доставать нельзя).

Часть основной памяти компьютера выделяется под так называемый аппаратный стек, который предназначен для того, чтобы хранить так называемые **стековые кадры**.

Когда какая-либо подпрограмма вызывается на исполнение, то для нее формируется стековый кадр, который автоматически помещается в стек. При этом, как только данная подпрограмма будет завершена, этот стековый кадр автоматически удаляется из стека.

Но, пока вызванная подпрограмма еще не завершена, она может вызвать другую подпрограмму, а та, в свою очередь, ещё какую-то, и т.д. В результате в стеке в какой-то момент одновременно может находиться множество стековых кадров еще не завершенных подпрограмм.

Каждый стековый кадр обязательно содержит адрес ячейки памяти, содержащей код той машинной команды, которая в вызвавшей подпрограмму функции следует сразу за вызовом данной подпрограммы. Это так называемый **адрес возврата**, он нужен для того, чтобы после завершения подпрограммы было известно, с какого места надо продолжить выполнение программы. Кроме адреса возврата стековый кадр может содержать ещё значения параметров подпрограммы и её локальные переменные (если они у подпрограммы имеются).

**Стековый регистр** - предназначен для хранения текущего адреса вершины аппаратного стека; его также называют указателем вершины аппаратного стека.

## 4. Вычислительный процесс, организация памяти  вычислительного процесса

Не зависимо от того сколько на компьютере имеется процессоров и процессорный ядер, операционная система (ОС) обычно выполняет сразу несколько вычислительных процессов. Управление этими процессами осуществляет ОС в автоматическом режиме. Если имеется несколько процессорных ядер, то каждый процесс может выполняться на отдельном ядре. Если ядро только одно, или ядер меньше, чем запущенных процессов, то планировщик ОС автоматически распределяет время между процессам, поочередно выполняя то один, то другой процесс. При этом можно считать, что каждый процесс выполняется на компьютере точно также, как если бы выполнялся только один единственный процесс. Это означает, что ОС выделяет каждому процессу отдельную область памяти, с отдельным виртуальным адресным пространством.

В принципе, есть возможность осуществления обмена данными между несколькими процессами, но это тема для отдельного разговора. Сейчас мы вообще не будем касаться этой довольно сложной темы.

Виртуальное адресное пространство каждого вычислительный процесса разделяется на следующие специальные области.

-  Область, в которой размещается скомпилированный, готовый для исполнения машинный код.
-  Область, называемая **динамической** памятью (или, по-другому, - кучей), в которой программа может размещать свои данные по мере надобности.
-  Область памяти, называемая **стеком** (или, по-другому, - автоматической памятью).

**Динамическая память** предназначена для размещения в ней промежуточных данных, необходимость в размещении которых возникает во время выполнения программы. Выполняемая программа в любой момент может сделать запрос к ОС на выделение памяти для временного размещения какого-либо объекта, и в результате размещения объекта в динамической памяти программа получает ссылку на этот объект (адрес вы деленного непрерывного участка памяти). После того, как захваченная память уже больше не нужна, она должна быть "освобождена", т.е. ОС должна получить от программы информацию о том, что ранее выделенный ей блок памяти больше не используется. Тогда ОС сможет выделить эту память данному или другому процессу еще раз по мере получения запроса на такое выделение.
Если этого не делать (не освобождать память), то будет происходить явление, называемое "утечкой памяти".  Утечка памяти может привести к невозможности дальнейшей работы программы по причине нехватки памяти при фактическом ее наличии.
Для предотвращения утечки памяти необходимо осуществлять управление памятью. Для управления памятью есть две возможности - это ручное управление, когда ответственность за правильное использование памяти полностью ложится на программиста, и автоматическое управление памятью, когда ответственность за это возлагается на среду выполнения. Эта функция среды выполнения называется  **"автоматической сборкой мусора"** -  GC (от англ. Garbage Collection). Есть языки программирования, в которых имеется возможность только ручного управления памятью (например, язык C), есть языки в которые базируются только на автоматической сборке мусора (например, Python, Julia и др.) Есть языки, в которые допускают как ручное, так и автоматическое управление памятью (например, С++).

**Стек** (или **аппаратный стек**) - эта область памяти называется также автоматической, она обеспечивает возможность выполнения подпрограмм.

**Стек** всегда занимает самую верхнюю часть адресного пространства, так, что при добавлении в стек новой порции данных, указатель (адрес) его вершины уменьшатся, а при извлечении данных - наоборот, увеличивается.

## 5. Виды трансляции

Трансляторы делятся на **интерпретаторы** и **компиляторы**.

**Работа интерпретатора** сводится к тому, что он разбирает **исходный код** на последовательность отдельных предложений, называемые **операторами**, каждый отдельный оператор транслирует в соответствующие машинные инструкции и запускает их на выполнение.

**Работа компилятора** состоит в том, чтобы преобразовать сразу весь исходный код в машинные инструкции целиком, выполняя при этом **оптимизацию машинного кода**, обеспечивающую на много более эффективное выполнение программы по сравнению с её интерпретацией.

В свою очередь, способы компиляции подразделяются на **статическую компиляцию** и **динамическую компиляцию** (JIT-компиляцию - "компиляция на лету").

**При статической компиляции** сначала из файла, содержащего исходный код, в результате трансляции (компиляции) получается другой файл, содержащий уже машинный код. Для выполнения скомпилированного таким образом кода, файл, содержащий машинный код, с помощью операционной системы (OC) загружается в память компьютера, и ОС передает загруженному коду управление вычислительным процессом, после завершения которого, управление компьютером вновь получает OC.

Примеры статически компилируемых языков программирования: C/C++,  Rust, Pascal,  Fortran.

**При динамической компиляции** машинный код создается во время выполнения программы непосредственно по исходному коду. Обычно исходный код программы представляет собой главную функцию, из которой вызываются различные вспомогательные функции (подпрограммы), как встроенные в язык программирования, уже представленные в виде двоичного кода, так и библиотечные или пользовательские, написанные на этом же языке программирования. И перед выполнением каждой вспомогательной функции сначала происходит её компиляция, а затем выполнение.

Примеры интерпретируемых языков: Python,  R, MATLAB. Эти языки, в отличие от статически компилируемых обеспечивают возможность работы в интерактивном режиме. В действительности, современные интерактивные языки (языки, использующие интерактивные среды), основываются на так называемых высокоуровневых виртуальных машины. Исходный код  на любом из таких языков сначала компилируется в машинный код соответствующей высокоуровневой виртуальной машины, а затем уже полученный код интерпретируется.

Кроме того, современные методы компиляции, как статической, так и динамической, могут базироваться на технологии LLVM. Эта аббревиатура расшифровывается, как низкоуровневая виртуальная машина, однако, считается, что эта расшифровка указывает лишь на происхождение названия, и связи с виртуальной машиной, подобной виртуальной машине Java, в этом названии усматривать не следует. Данная технология в настоящее время рассматривается как весьма прогрессивная, обеспечивающая высокую эффективность, почти не уступающую статической компиляции.

JIT-компиляция на основе LLVM, с одной стороны, также обеспечивает возможность интерактивной работы с программным  кодом в интерактивных средах, например, в REPL или в блокнотах Jupyter. Но, с другой стороны, - позволяет получать высокоэффективный исполняемый код, почти не уступая статическим компиляторам таких языков, как C или Fortran.  

Язык программирования Julia является примером языка с JIT-компиляцией на основе LLVM.  

## 6. Статическая и динамическая типизация

Кроме способа компиляции языки различаются еще по наличию или отсутствию так называемой динамической типизации.

Статическая типизация подразумевает, что с каждой переменной жестко связывается данных, таким образом, что в данную переменную может быть записано (помещено) значение только определенного типа. Т.е. при статической типизации в процессе выполнения программы тип переменной изменен быть не может. 

Динамическая же типизация позволяет изменять тип значения, хранящегося в данной переменной в процессе выполнения программы.

Каждый из подходов к типизации имеет свои плюсы и минусы. Статическая типизация обеспечивает более высокую надежность и эффективность программного кода. Динамическая типизация обеспечивает большую гибкость, обычно полезную при обработке данных, когда типы значений могут быть разными. Например, некоторый список может содержать как целочисленные значения, так и дробные числовые значения. И при обработке такого списка бывает удобно, чтобы не требовалось заранее определять какого именно типа будут обрабатываемые значения.

Такие языки, как C/C++, Rust, Pascal - являются примерами языков со статической типизацией.  Например, в языке C/C++ следующий код приведет к ошибrе:
```julia

int n = 0; 
n = 1.5; // - ошибка!
```
Точнее говоря, этот код не может быть скомпилирован, компилятор сообщит о недопустимости такого использования переменной.

С другой стороны языки Julia, Python, R, MATLAB - это примеры языков с динамической типизацией. Например, в любом из этих языков возможно выполнить код
```
n = 0
n = 1.5
```
В частности, если говорить о языке Julia, то здесь в первой сточке создается переменная  целого типа `Int64`. А в результате выполнения второй строчки та же переменная получит тип `Float64`. В других языках та же самая запись на уровне типов может означать иное.

Вообще говоря, нестабильность типа переменной в программе на языке Julia - это одна из причин, которая будет препятствовать компилятору в получении высоко эффективного кода. Поэтому в языке Julia имеется возможность фиксации типа переменной. Например, возможен следующий код
```julia
n::Int = 0
n = 1.5 # - ошибка!
```
Здесь уже, при попытке выполнения второй строчки этого кода, произойдет ошибка.  

Динамические переменные, на самом деле, содержат не значение (какого-либо типа), а ссылку (т.е. адрес в памяти) на ячейку памяти, в которую записано значение того или иного типа. Таким образом, поскольку длина ссылки не зависит от типа значения, на которое она ссылается, в памяти сама переменная занимает одно и тоже место. При этом сами данные, на которые ссылается эта переменная, могут иметь любой размер.
